System

MacDirStat is one macOS process. Scanning and pixel shading run off the main thread, and everything that changes the tree runs on it.

What each part owns

PartOwnsRuns on
AppStateThe phase, the root, the selection, the view root and most actions a user can start. It is the only object that starts a scan or a trash.Main thread
DiskScannerThe directory stack, the worker threads and the progress counters for one scan. A new instance runs for each scan.Its own threads
FileNodeOne node's name, size, counts, inode and links to its parent and children.Background threads during a scan, then the main thread
TreeEditThe edits that remove a node or splice in a folder rescan, including totals and hard-link owners.Main thread
FileIdentityThe identity check that runs before a trash or a folder rescan.Main thread
DirectoryOutlineThe Tree's rows, its sort order and its cache of sorted children.Main thread
ExtensionListFile Types' rows, up to 400 of them. A click sets or clears selectedExtension.Main thread
TreemapCanvasThe Map's layout, its picture and the overlays for hover, selection and extension.Main thread
TreemapRendererTurning one render job into one image. It holds no state.Render queue

Who may change the tree

  • While a scan runs, each worker writes only the nodes of the directory it took from the stack.
  • AppState receives the finished root on the main thread, and only the main thread changes nodes after that.
  • Removing a node and splicing a folder rescan both go through TreeEdit, so ancestors' totals and sort order stay correct. Trash and rescan has the steps.
  • A change bumps treeVersion. The Tree and The Map reload when that number changes.

How a build reaches a Mac

A v* tagStarts the Release workflow on a macos-15 runner.
↓ source at that tag
Scripts/test.shRuns the test suite. A failure stops the release.
↓ tested source
Scripts/package-release.shBuilds arm64 and x86_64, and merges them with lipo.
↓ the app bundle
Is the DEVELOPER_ID_IDENTITY secret set?
YesThe build has a Developer ID signature, plus notarization if the notary settings are also present.
NoThe build has an ad-hoc signature, and macOS blocks the first launch until the user allows it.
↓ DMG and zip
gh release createPublishes a GitHub Release with both files.
  • The app runs on macOS 14 or later. Without Full Disk Access, macOS keeps some folders from the scanner and they count as unreadable.
  • The CI workflow runs the tests and Scripts/build-app.sh on pushes to main and on pull requests, then uploads the app as a workflow artifact. It publishes no release.
