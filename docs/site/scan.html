Following a scan

The user starts the app with --scan ~/Downloads, and seven steps later the window shows that folder's tree and map.

From path to window

1
The app reads the path
  • MacDirStatApp finds --scan, expands the tilde and calls scan on AppState.
  • The welcome buttons, ⌘O, a dropped item and a Finder open all call the same method.
2
A scanner starts its workers
  • AppState cancels any running scan, sets the phase to scanning and starts a background job.
  • DiskScanner resolves symlinks in the path, so the root's name is a symlink-free path.
  • It starts twice as many workers as active cores, with a minimum of 4 and a maximum of 24.
3
Workers read each directory
  • Each worker takes a directory from a shared last-in, first-out stack and pushes the subfolders it finds.
  • getattrlistbulk returns names, types, sizes and inodes for a whole directory in a few calls, which replaces one lstat per entry.
  • Movies/trip.mov has two links, so whichever link a worker reaches first keeps the 2.1 GB and the other gets size 0.
4
The window shows progress
  • Every 0.1 seconds a timer copies the file, folder and byte counters and the current path to AppState.
  • ScanningView draws them. Its Never mind button or the Esc key cancels the scan.
5
The scanner adds up totals
  • finalize walks the tree from the bottom up, totals each folder and sorts its children biggest first.
  • A modified time more than a day in the future doesn't count toward a folder's Last Change.
6
The main thread takes the tree
  • If a newer scan or a cancel replaced this scanner, the result is dropped and finishScan never runs.
  • finishScan stores the root and the extension totals, and builds the hard-link registry.
  • The 14 biggest extensions get the palette's colors in order. Every other extension gets a muted color derived from its ID.
7
The panels draw it
  • The phase becomes ready and treeVersion goes up.
  • The Tree opens the root, and its biggest item if that item is a folder. File Types lists the extensions. The Map starts its layout and render.

How a scan can end

OutcomeWhenWhat the user sees
FinishedEvery directory on the stack was read.The tree, File Types and The Map, with the time taken in the footer.
CancelledThe user pressed Never mind.The previous tree if there was one, otherwise the welcome screen. The partial result is dropped.
MissingThe path doesn't resolve.A toast that says the folder couldn't be read, on top of the previous tree or the welcome screen.
Root unreadableThe path exists and its directory can't be opened.A map with an empty root. This replaces any previous tree.
Some folders unreadableA folder below the root can't be opened.The rest of the tree, a lock icon on that folder and a count in the footer.

What the numbers count

  • Size is the allocated bytes that getattrlistbulk reports, so a sparse file can be smaller than its logical size.
  • A symlink is a node with its own size. The scanner doesn't follow it.
  • A scan doesn't enter /System/Volumes, /Volumes, /dev, /net, /home, /.vol, /.nofollow or /.resolve. These are volume mounts, the Data-volume mirror and virtual file systems. The list applies to folders found during a scan, so a user can still pick a path such as /Volumes/Backup as the root.
