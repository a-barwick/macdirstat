Open questions

The repo doesn't settle these, either because nothing in it measures the claim or because the code's behavior may not be what was intended.

Claims with no evidence in the repo

ClaimWhat's missingHow to settle it
About 3 million files in roughly 30 secondsThe README states this with no benchmark, date or hardware model.Time a scan of a whole disk and record the machine.
Sizes match duThe test suite compares totals to st_blocks, and nothing runs du. APFS clones and compressed files aren't covered.Compare a scan to du on a folder that holds clones.

Intel builds workThe workflow builds x86_64 and the tests run on the runner's own architecture. Nothing records a launch on an Intel Mac.Launch a release build on an Intel Mac.

Questions about published releases

  • The repo has a v1.0.0 tag. It doesn't record whether the Release workflow succeeded for that tag.
  • Repository secrets aren't visible from the code, so the repo can't show whether published builds are signed. The README says they aren't.
  • The first-launch steps in the README depend on macOS behavior, and the repo has no record of them being checked on each macOS version.
