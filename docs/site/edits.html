What the identity check rejects

FailureCondition
unknownIdentityThe node has no recorded inode.
missingThe parent folder or the item no longer resolves.
pathRedirectedThe parent's path resolves somewhere else, such as a symlink placed where a folder was. A folder moved away with nothing in its place gives missing.
replacedThe path holds an object with a different inode, or its type changed between file and folder.

The check works because each scan root is a symlink-free path, so a stored path only stops resolving to itself when something changed. The check and trashItem are separate calls, so a swap in the moment between them isn't detected.

Folder rescan outcomes

On a folder below the root, Rescan This Folder runs the identity check, scans the folder on a background queue, and then applies the result on the main thread. On the root it runs a full rescan, with no identity check.

ResultWhenWhat happens
SplicedThe scan read the folder.The fresh subtree replaces the old node, and totals and hard links update.
Spliced, with a countThe folder read, but some folders inside it didn't.As above, and a toast gives the count of unreadable folders.
unreadableThe folder couldn't be listed at all.The old numbers stay, and a toast says so.
staleTargetThe old node left the tree during the scan.The result is dropped with no message.
Older generationA full scan finished or the map closed during the rescan.The result is dropped with no message.
No resultThe path no longer exists.The tree stays as it was, and a toast suggests a full rescan.

A full rescan with ⌘R skips this path. It starts a new scan of the root, resolves the path again and replaces the tree when it finishes.

  • HardLinkRegistry keeps every link of every multiply-linked file, grouped by inode, with the file's allocation.
  • reconcile drops links that left the tree, keeps one owner and sets that owner's size to the allocation.
  • A folder rescan adds its fresh links and reconciles the same way, so rescanning Archive doesn't count the file twice.

What runs with no identity check

  • Reveal in Finder and Open pass the node's stored path straight to NSWorkspace.
  • Copy Path reads no disk state.
  • A full rescan doesn't use the check, because it builds a new tree from the root path.
